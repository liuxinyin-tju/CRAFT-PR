# evaluate Directory Guide

This directory performs **execution evaluation and coverage statistics** on the unit tests generated by each baseline method (ours, ours_wo_con, ours_wo_re, ours_wo_str, ours_qwen, ours_gpt, Cleverest, Panta, etc.). It produces three core metrics:

- **Patch coverage**: the fraction of patch-modified lines covered by the generated tests (`calculate_patch_coverage.py`)
- **CAR (Coverage-Aware Rate)**: the fraction of PRs for which the generated tests improve coverage of patched functions compared with the original tests (`compare_coverage.py`)
- **F2P (Fail-To-Pass)**: the number of tests that change from failing to passing after the patch is applied, and the corresponding number of PRs (`execute.py`)

The 8 evaluated projects: `fastjson2`, `dubbo`, `gson`, `guava`, `jackson-core`, `jackson-databind`, `jackson-dataformat-xml`, `nacos`.

---

## Test Result Data Format

Each baseline directory (e.g., `./ours/{project}.json`) contains a JSON array. The fields of each element are:

| Field | Description |
| --- | --- |
| `instance_id` | PR instance ID, format `mswebench/{org}_m_{repo}:pr-{number}` |
| `method_name` | Focal-method locator, format `relative/file/path#methodName(parameter signature)` |
| `focal_method` | Source code of the focal method |
| `test_file_path` | Absolute path of the test file inside the container, e.g., `/home/{project}/.../XxxTest.java` |
| `test_code` | Generated test code |
| `status` | Generation/execution status, e.g., `success` |
| `coverage_info` | Function coverage info: `instruction_coverage`, `branch_coverage`, `line_coverage`, `start_line`, `end_line`, `total_lines_num`, `missed_lines_num`, `missed_lines` (line numbers relative to `start_line`) |
| `test_result` | Test execution result: `{total, passed, failed}` |

## 1. `calculate_patch_coverage.py` — Collect Patch Coverage

Computes the **coverage of patch-modified lines** for each focal method.

**Key configuration (inside `main()`):**

```python
repo_name_list = ['fastjson2']          # list of projects to evaluate
test_result = f"./ours/{project_name}.json"
patch_info  = f"../locate/results_with_requirement/{project_name}.json"
```

**Run:**

```bash
cd evaluate
python calculate_patch_coverage.py
```

> Results are currently printed to the terminal (the file-writing code is commented out; uncomment it and specify an output path if needed).

---

## 2. `compare_coverage.py` — Compute CAR (Coverage-Aware Rate)

Compares the function-level `missed_lines` **after** running the generated tests with those of the original tests (before the patch), and counts how many PRs achieve a coverage improvement.

**Key configuration (inside `main()`):**

```python
project_list = ['fastjson2', 'dubbo', 'jackson-databind', 'jackson-core',
                'jackson-dataformat-xml', 'gson', 'nacos', 'guava']
strategy = 'ours'   # ours / ours_wo_re / ours_wo_con / ours_wo_str
```

**Run:**

```bash
python compare_coverage.py
```

---

## 3. `execute.py` — Compute F2P (Fail-To-Pass)

Invokes the multi-swe-bench harness to compile and run the generated tests inside containers, then parses the run logs to compute F2P.


**Key configuration (inside `main()`):**

```python
baseline_name = "ours"   # ours / ours_wo_con / ours_wo_re / ours_wo_str / ours_qwen / ours_gpt
pair_list = [('fasterxml', 'jackson-dataformat-xml'), ('google', 'gson'),
             ('apache', 'dubbo'), ('alibaba', 'fastjson2'),
             ('fasterxml', 'jackson-core'), ('fasterxml', 'jackson-databind'),
             ('google', 'guava'), ('alibaba', 'nacos')]
```

Input-file naming convention per baseline: `ours` and `ours_wo_str` use `{project}.json`; `ours_wo_con`, `ours_wo_re`, `ours_qwen`, and `ours_gpt` use `{project}_0.json`.

**Run:**

```bash
python execute.py
```

**Dependencies:** `ResultParser.TestResultParser` and `LogAnalyzer.TestLogAnalyzer` (local modules under the analyzer directory), plus the harness and configs under `../multi_swe_bench/`.
